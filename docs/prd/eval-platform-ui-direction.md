# Agent Eval Control Room · UI 方向

## 设计目标

面向正在调试 Agent、Runtime 和评测器的工程师。打开平台后的第一任务是回答：

1. 哪些评测正在运行？
2. 这次运行在哪个 Trial 失败？
3. 失败发生在 Agent、工具、上下文还是验证器？
4. 我下一步应该查看哪条证据？

因此界面以“可追踪的评测闭环”为主线，而不是以单纯的成功率报表为主线。

## 视觉方向

- **画布**：暖白工程纸张背景，降低大段日志和表格内容的阅读负担。
- **品牌强调色**：柔和 acid lime，仅用于主行动、当前导航和成功/完成态。
- **语义色**：蓝色表示执行中，琥珀表示排队，珊瑚表示失败；不用于装饰。
- **深度策略**：低对比边框 + 极轻阴影，面板依靠层级和留白分组，不依靠厚重卡片。
- **密度**：4px 基础间距，控制区 12–16px 内间距，详情区按时间线需要增加呼吸感。
- **字体**：DM Sans 负责阅读，DM Mono 负责 Job、Trial、事件和指标，强化工程数据的可扫描性。

## 竞品参考与取舍

- **LangSmith**：将 Dataset、Experiment、Example/Run 和评测分数放进同一条可下钻链路；本平台对应为“评测集 → 实验 → Trial → 事件/证据”。
- **Braintrust**：把每次评测保留为可比较的实验快照，并支持并排查看结果；本平台在实验记录页提供状态筛选、搜索和多实验对比卡。
- **Phoenix**：把 Trace、Evaluation、Dataset 和 Experiment 放在同一个调试闭环中；本平台优先展示失败归因和关键事件，再按需展开第三方输出与原始日志。

本次不直接复制竞品的深色终端外观、复杂图表或过多导航，而是保留面向 Agent 工程师最有价值的三件事：快速找到异常实验、比较质量变化、沿证据链定位原因。

## 页面结构

```text
┌──────────────────────────────────────────────────────────────┐
│ CodeDen / Agent Eval Control Room       Worker queue · refresh │
├──────────────┬───────────────────────────────────────────────┤
│ 评测集        │ 页面标题 + 当前任务                          │
│ 实验记录      │ ┌─────────────────┐ ┌─────────────────────┐ │
│              │ │ 评测目录 / cases │ │ 执行计划 / model    │ │
│ Runtime      │ └─────────────────┘ └─────────────────────┘ │
│ online       │ 实验记录 → Run → Trial → Trace / 诊断 / Diff │
└──────────────┴───────────────────────────────────────────────┘
```

## 可交互闭环

- 评测集按钮：切换当前 Dataset；复选框：加入跨库并行运行。
- 具体题目：搜索、单选/全选测试用例。
- 执行计划：选择模型、重复次数；真实模型需要显式确认额度消耗。
- 创建实验：提交 Job 后自动切到实验记录，并持续刷新状态。
- 实验记录：点击任意 Job 进入详情；结束任务可勾选删除。
- 详情下钻：Run 卡片 → 并发 Trial → 单条 Trial 结果 → 失败诊断、关键事件、验证器原始输出、Diff。
- 实时态：EventSource 增量合并事件，当前事件用酸橙脉冲点突出；页面支持 reduced-motion。
