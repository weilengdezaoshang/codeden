# 环境制作：从开源实践到页面交互

更新：2026-08-31 · v0.7 · 待评审设计与交互演示，未接真实构建服务。

[打开环境制作原型](eval-platform-closed-loop.html#environment)。常规入口：Trace 审核 → 整理用例 → 环境 → 制作环境。

## 先补齐缺失的一环

环境不是用户机器上的一个目录，也不是已经跑完任务的容器快照。作者需要交付可重建的初始项目、运行约束、独立验证材料和任务自检证据。审核者可以复用现有版本；没有合适版本时进入制作子页，返回后继续原用例，不丢任务草稿。

完整闭环：整理任务 → 制作/选择环境 → 确认验收 → 发布用例与数据集版本 → 独立运行 → 查看结果与证据 → 人工修订任务/环境/验收 → 新版本重跑。环境版本、用例版本、数据集版本与运行记录分别保留，不能覆盖历史证据。

| [SWE-bench Docker Setup](https://www.swebench.com/SWE-bench/guides/docker_setup/)                                                    | 基础、环境和实例分层构建以复用缓存                     | 作为后端构建缓存设计依据；页面不让作者手动管理缓存层 |

项目自身的选择：默认任务容器不访问外网、提供域名白名单、两次干净实例复现、独立验证容器。不同社区框架的网络默认值和验证模式不同，不能将这些选择描述为通用强制规范。构建依赖下载、Agent 的模型服务连接与任务容器网络分开治理。

Oracle 是作者提供的参考解，用于证明题目可解，不是被测 Agent 的成绩。Nop 是不操作的对照：本页是修复缺陷题，空跑应失败；无需行动即可正确的任务应另定义负例。代码测试不自动覆盖“如实汇报”等语义判据。

## 四步交互

| 步骤         | 可操作的内容                                                    | 视觉组织与下一步                          |
| ------------ | --------------------------------------------------------------- | ----------------------------------------- |
| 配置环境     | 名称、CPU、内存、超时、网络、来源与授权说明                     | 常用字段直接展示；配置文本按需展开        |
| 准备项目     | 编辑 Dockerfile、初始代码、数据、依赖声明；添加相对路径文本文件 | 文件列表 + 单文件编辑器，禁止填写主机路径 |
| 验证与参考解 | 编辑独立测试、验证器构建配方、参考解                            | 材料分区与制品传递方向，明确平台保管边界  |
| 构建与自检   | 启动/取消检查、点击阶段日志、修正材料、人工复核、保存版本       | 六个检查节点，不使用自由拖拽 DAG          |

Node 示例是独立合成项目：初始 `sum([])` 抛错，参考解让其返回 0，验证器同时检查空数组、普通数组与含负数情况。它是可编辑的制作起点，不代表从原始 Trace 自动复原了真实项目，也不是任意任务通用模板。

自检顺序：材料检查 → 构建镜像 → 启动与重置 → 参考解通过 → 空跑不通过 → 重复复现。每个节点显示文字状态和日志，颜色只辅助区分。构建失败不能算 Agent 解题失败，参考解失败也应先修正任务材料。

## 版本与状态规则

- 草稿可随时保存与离开；本原型只保留当前页面内存，刷新清空，生产版需要服务端持久化。
- 检查进行中冻结材料编辑；支持取消，已完成阶段不丢失。
- 失败保留日志并停止后续阶段，提供“检查构建配方”或“检查验证与参考解”入口。
- 材料或任务输入变化使旧报告过期、撤销复核状态；必须重新检查后才可保存版本。
- 检查通过后仍需作者确认任务匹配、授权、隐私和验证隔离。前端复选框不是权限或安全控制。
- “保存环境版本并使用”固定材料副本并回填用例的环境选择；相同内容重复使用不生成第二个版本，变更内容生成新版本。
- 环境保存不会自动发布用例/数据集；回填会使原用例的材料检查失效，需继续验收和入库。
- 历史用例继续引用旧环境版本，不被后来编辑覆盖。

## 原型真正做了什么

本地材料检查检查名称、必需文件、JSON 可解析性、超时范围和必要说明；可编辑文本从不执行、不上传。六节点中的构建与验证结果由明确标注的演示分支生成，不能证明 Dockerfile 或测试实际可运行。可切换所有阶段通过、构建失败、空跑误通过、两次复现不一致。

保存版本使用浏览器 SHA-256 计算当前配方、文件和任务输入的摘要。它是真实的内容摘要，但**不是镜像 digest，不是构建证明，也不是签名**。配置预览参考目录语义，未验证 Harbor 格式兼容性；未实现 ZIP 导入导出、真实容器、远程仓库拉取、付费试跑或生产发布。

## 后端落地边界（尚未实现）

| 记录               | 应冻结的关键信息                                                               |
| ------------------ | ------------------------------------------------------------------------------ |
| EnvironmentDraft   | 租户/作者、来源授权、材料对象引用、资源限制、网络策略、修订号                  |
| EnvironmentBuild   | 配方摘要、构建器版本、构建日志、实际基础镜像与产物 digest、成功/失败原因       |
| EnvironmentCheck   | 精确材料修订与任务契约摘要、Oracle/负例/重置复现证据、检查器版本、人工审核记录 |
| EnvironmentVersion | 不可变镜像与材料引用、检查证据、发布者与时间、可撤销的可用状态                 |
| CaseVersion        | 独立任务、criterion IDs、验证契约、环境版本、可复用来源；禁止漂移到 latest     |

构建 Worker 与评测 Worker 是不同职责。不得在 API 主进程、本机项目目录或带 Docker socket/平台凭据的通用容器里执行上传脚本。使用隔离执行器，限制构建与试跑资源和网络；构建制品按租户授权，缓存键包含影响输出的完整依赖。

Agent 工作区只包含初始项目与公开要求；交付后按白名单收集制品，在独立验证环境中检查。必须防范路径穿越、符号链接越界、超大制品、恶意依赖与测试篡改；评分文件由平台控制，不直接信任 Agent 写出的 reward。隐私、许可证、恶意内容和可复现性检查需要独立服务及人工审查，不能以字段齐全代替。

保存/发布接口应使用修订号校验、幂等键与事务，服务端重验当前检查是否匹配材料摘要及完整任务契约。生产中判据变化同样需要失效检查；前端演示只追踪传入的任务文本与制作材料，不能作为后端门禁实现。

不因“制作环境”隐式调用付费 Agent 或 judge。额外真实试跑需独立展示配置和预算并确认。后续对接应先完成隔离构建、自检证据和版本契约，再接评测执行，不以可点击原型代替后端验收。
