# CodeDen 评测平台 · 可交互 PRD v0.2

状态：需求与交互草案。交互原型中的任务、输出、分数和审核记录均为合成演示数据；不是当前平台已上线的能力声明。

2026-08-31 修订：重复评测及同条件对比纳入首版，详细规则见[重复评测实验规格](eval-repeat-experiments.md)。本轮仅更新文档；原型仍为旧版单次演示，其脚本测试不能作为重复执行验收。

## 1. 产品目标

用户选择评测集、被测配置和每题执行次数，确认总试次及预算后由后端自动执行。默认每题 5 次，支持 2–20 次；显式单次冒烟为 1 次，不用于判断稳定性。每次都从干净环境开始并独立判卷，不要求用户手动重跑。需要定位时逐层展开：实验汇总 → 案例多次成绩 → 单个 Trial → 调用链与判卷证据。

第一版以离线评测闭环为交付目标。页面、后台执行入口和共享业务代码位于同一评测平台应用范围；进程是否分开不影响页面交互。Agent 终端入口、会话与任务执行循环保持独立。

### 首版范围

| 功能       | 首版目标                                                                                       |
| ---------- | ---------------------------------------------------------------------------------------------- |
| 评测集     | 从服务端登记的内置回归评测集选择，不允许浏览器传任意路径、命令或代码                           |
| 模型       | Mock 流程验证；服务端显式开启后可选择配置的真实模型，创建时确认付费                            |
| 任务       | 创建、排队、运行、查询、取消；任务与结果持久化                                                 |
| 重复执行   | 冻结案例数 × 每题次数的全部 Trial 计划；成功失败均执行剩余计划，每次重置环境与会话             |
| 统计与对比 | 计划通过占比、有效判定成功率及覆盖率、每题 Wilson 区间；完整同条件实验只作观测对比，不自动晋级 |
| 执行历史   | 保存每次离线评测；按集合、状态、时间筛选和运行 ID 查找，分页回看冻结配置、结果与证据           |
| 汇总       | 已完成数量、通过数量、样本失败与运行异常分别统计、耗时、Token 与采集覆盖率                     |
| 样本       | 任务要求、模型输出、各 Grader 结果、评分依据、失败证据                                         |
| Trace      | 按顺序浏览提示词构建、模型请求/输出、工具调用/结果与验证事件；关联 runId、trialId              |
| 版本       | 记录实际数据集/fixture、Agent、Grader、环境及模型配置的版本或摘要                              |
| 工程化     | 中文测试描述、单测/数据库集成/浏览器测试分层、提交门禁与独立测试环境                           |

### 后续范围（原型可预览，非首版验收承诺）

- 授权线上 Trace 上传、接收、抽样与异步评分。
- 人工复审工作队列、人员分配、真实审核持久化与操作审计。
- 候选场景脱敏、独立 fixture 构造、复核及离线评测集晋级。
- 多人登录、项目权限隔离、配额与统一费用结算。
- 任意历史 Agent 版本运行、完整用户环境重放。

第一版拟仅监听本机 loopback；是否首批支持多人部署尚待确认。没有认证与权限隔离前不得开放到公网。

## 2. 主要交互

### 2.1 创建评测

1. 选择已登记的评测集，看到包含的样本数量与评测维度。
2. 选择模型。Mock 明确标注“仅验证流程，不代表真实模型质量”。
3. 确认模式、每题次数和服务端预算策略；展示案例数 × 次数 = 总试次数。真实调用费用包含全部试次及判卷；未确认不能创建。页面不填写或回显 API Key。
4. 提交后按钮进入等待态；重试同一请求使用同一 requestId，服务端确保不会重复创建。
5. 后端在同一事务中保存任务、冻结配置和全部 Trial 计划并入队，成功后返回任务编号；入队失败必须回滚。每个 (jobId, caseId, repetitionIndex) 唯一。
6. 进入任务详情。没有空闲执行槽位时显示排队，不伪装成运行中。

### 2.2 查看进度

- 顶部呈现案例数、每题次数、已处理/计划试次与当前阶段；不编造精确剩余时间。
- 每个 Trial 完成后立即可查看，案例汇总同步更新，不必等待整场结束。
- 页面刷新、返回列表或关闭浏览器不取消已创建的后台任务。
- 查询断网显示“进度暂不可用，上次同步时间…”，不把查询失败视为评测失败。
- 连续轮询采用退避；任务终态后停止高频轮询。
- 取消先显示“正在停止”；后台确认后才进入已取消。已完成结果保留，未执行样本不评分。

### 2.3 查看结果

“执行结束”不等于“全部通过”。任务状态与样本评分是两个独立维度。

| 内容     | 展示要求                                                                                                        |
| -------- | --------------------------------------------------------------------------------------------------------------- |
| 通过率   | N=P+F+U+M；分别展示 P/N、P/(P+F)、(P+F)/N，未判定 U 与未完成 M 不隐藏；分母为 0 显示暂无有效判定                |
| 每题成绩 | 显示通过几次/计划次数，保留所有试次与实际回答；重复模式给出每题 95% Wilson 区间及假设说明，不显示虚假稳定性结论 |
| 样本失败 | 模型行为未满足规则，与 API 失败/环境失败分开展示                                                                |
| 人格评分 | 显示具体规则、判定结果、引用的输出片段、Grader 版本；不只有一个总分                                             |
| Token    | 输入/输出、实际测量或估算来源、采集覆盖率；缺失不能写成 0                                                       |
| 费用     | 首版可不展示金额；只有模型定价版本和完整用量齐备时才能计算，估算须标注                                          |
| 失败分类 | 作为定位线索，不把自动归因当成已确认根因                                                                        |

### 2.4 从失败定位到证据

先展示每题多次成绩，再选择具体试次查看任务要求、该次模型输出和未通过的评分项，不把最好一次当作全题结果。点击“查看链路”进入深层信息：

1. 左侧按执行顺序列出事件，标注类型与状态。
2. 右侧展示选中事件的可读信息，原始 JSON 作为折叠的次级视图。
3. 模型请求可看实际发送的消息和提供的工具清单；模型输出可看文本、工具调用和用量。
4. 工具调用包含名称、参数、结果/错误及调用关联标识；没有采集到的字段显示未采集，不推造。
5. 评分节点显示规则、版本、判定和证据引用，可跳转到对应输出/工具事件。
6. 提示词不存在或已截断时，显示内容缺失/截断原因。人格评测不能仅凭 metadata-only Trace 给出确定结论。

原型中展示的可读标签不是新增协议字段的完成声明。实施时应从现有 RunEvent、TrialResult 和评分事件映射；缺少关联字段需扩展有版本的契约与测试。

### 2.5 离线评测执行历史

执行历史纳入首版验收，属于离线评测入口。成功创建的所有任务（包括排队、运行、失败、取消和中断）均须可找回，不只展示最新运行。默认全部集合、创建时间倒序并以任务 ID 稳定排序，支持服务端分页、集合/状态/创建时间筛选及任务 ID 精确查找。

摘要显示任务编号、集合名称与冻结版本、Agent / 模型、执行状态、创建/开始/结束时间、已处理/总数和结果分类数量。进入详情后使用历史配置和证据；刷新、关闭浏览器或服务重启不丢失记录。当前创建所选集合不能改变旧任务的结果归属。

总数明确为计划 Trial 数，另保存案例数、每题次数和模式。旧单次历史保持 R=1，不合并到新实验。P0 支持基于冻结配置创建对比实验，重新选择可用被测配置、确认预算和费用并关联 baselineJobId；题目、环境、判卷、次数及资源策略一致且判定完整才展示观测差异，不宣称显著改善。必要旧依赖不可用时拒绝，不静默替换。

区分无历史、筛选无匹配和查询失败；查询重试不创建任务。再次启动生成新任务，不覆盖旧记录，不自动复现旧配置或产生付费重跑。首版不提供历史删除操作；证据不可访问时明确说明原因。

完整范围、重跑边界及验收场景以[闭环 PRD 的「离线评测执行历史」](eval-platform-closed-loop.md#离线评测执行历史p0)为准；这是需求补充，不代表原型或后端已经实现。

## 3. 状态与异常

| 状态        | 用户看到什么             | 后端约束                                           |
| ----------- | ------------------------ | -------------------------------------------------- |
| queued      | 排队中，可取消           | 已持久化且已入队，尚未执行                         |
| running     | 执行中，逐样本显示进度   | 原子领取、限并发、心跳与执行时限                   |
| cancelling  | 正在停止，已完成结果保留 | 向执行链传递取消，停止新调用并清理执行资源         |
| completed   | 执行完成，另看通过率     | 允许存在评分未通过的样本                           |
| failed      | 运行失败，提示可操作原因 | 无效配置、不可恢复执行错误或总超时；不暴露密钥     |
| cancelled   | 已取消                   | 不再开始新样本，不用“全部失败”替代未执行           |
| interrupted | 执行中断                 | 重启或心跳失效；保留已完成结果，不自动重复付费任务 |

边界要求：

- 重复点击/网络超时重发：相同 requestId + 相同参数返回原任务；参数不同时返回冲突。
- 排队取消与领取竞争：只有一个原子状态转换胜出，取消成功后不得调用模型。
- 完成与取消竞争：终态不能被迟到回调覆盖；具体竞态规则由状态事务统一实现。
- 模型限流/鉴权失败：展示运行异常与安全错误码；不要归因为人格或任务能力差。
- 数据集、Grader 或模型配置在排队后变化：拒绝混用新旧版本，要求创建新任务。
- 测试命令卡住：有时限、取消和进程/容器清理；Worker 不等于沙箱。
- 大量结果/长 Trace：分页或按需加载，不把全部内容一次传到浏览器。
- 超大事件或已脱敏内容：展示明确标记；不得把截断证据当完整记录给出高置信度判断。
- 查询失败与执行失败分别建模，页面允许重新连接，而不是重新创建任务。
- 计划内重复 Trial 与故障 ExecutionAttempt 分开：默认仅未调用 Agent 的准备故障可自动重试 1 次；不确定是否调用的中断不自动重跑，不增加统计分母。评分传输/格式故障最多重试 1 次，合法失败不触发重评。
- Trial 执行生命周期与 verdict 独立；取消、心跳丢失及整场预算耗尽保留已有结果，未完成不等于任务失败。租约与终态提交必须防止重复计数及迟到写入，具体状态见重复评测规格。

## 4. 人工复审（后续预览）

默认界面只包含：用户任务、最终回答、机器评分理由、关键证据。

审核员选择：认可评分 / 评分有误 / 证据不足。否定机器评分时必须写原因。提交后保存独立的审核记录，不覆盖原始 Trace 和原始机器评分。

审核记录至少关联 sampleId/trialId、原评分版本、审核者、结论、说明、时间和修订号。多人并发审核需要版本冲突提示；审计保留修改历史。

需要详细排查时再打开 Trace。人工确认失败并不自动授权上传隐私、用于训练或加入离线评测集。

## 5. 离线与线上边界

| 路径                 | 执行位置与数据来源                         | 与当前用户任务的关系                                   |
| -------------------- | ------------------------------------------ | ------------------------------------------------------ |
| 离线评测             | 平台执行受控评测集与独立 fixture           | 用户在平台显式创建，不是重放用户私有项目               |
| 线上评测（后续）     | 用户授权上传的 Trace 在服务端异步评分      | 不阻塞用户交互；平台评分模型费用与用户任务费用分开记录 |
| 人工复审（后续）     | 审核队列中的必要证据                       | 不默认展示全部隐私，也不改变用户任务结果               |
| 离线候选晋级（后续） | 脱敏、人工确认、构造独立 fixture、重新验证 | 不能把原始用户代码/对话直接复制进训练或评测集          |

## 6. 接口与数据模型

| 接口                                           | 语义                                                                                                                                            |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| GET /api/catalog                               | 返回可选评测集、模型及是否为 Mock                                                                                                               |
| POST /api/jobs                                 | 接收 requestId、datasetId、modelId、allowPaid、mode、repetitionsPerCase、agentConfigId、budgetPolicyId、可选 baselineJobId；返回 202 与任务编号 |
| GET /api/jobs                                  | 分页查询离线执行历史摘要；支持 datasetId、status、创建时间范围和任务 ID 筛选，按创建时间与 ID 稳定倒序，不返回全部 Trace                        |
| GET /api/jobs/:id                              | 状态、进度、版本、结果摘要与样本                                                                                                                |
| POST /api/jobs/:id/cancel                      | 幂等取消请求，运行中先返回 cancelling                                                                                                           |
| GET /api/jobs/:id/trials/:trialId/events       | 分页读取该任务下的事件，防止跨任务串读                                                                                                          |
| GET /api/jobs/:id/cases                        | 分页案例多次成绩汇总                                                                                                                            |
| GET /api/jobs/:id/trials?caseId=...            | 分页独立试次，包含 repetitionIndex                                                                                                              |
| GET /api/jobs/:id/comparison?baselineJobId=... | 只读比较兼容性、观测差异及不可比原因，不触发执行                                                                                                |

公共字段使用人类可读标签：run/job 表示一次评测任务；trial 表示一个样本的一次执行；Grader 表示评分器；Trace 表示实际执行链路。界面不要求审核员先理解内部字段名。

任务记录保存提交参数、不可变配置快照、状态与进度、版本、时间和安全错误消息。TrialResult 保存各样本评分结果；RunEvent 保存详细调用事件。审核结论作为单独实体追加。

详细字段及迁移以重复评测规格为准；新增 schema/statistics 版本，旧请求省略次数不能意外触发多倍付费，新版要求显式传模式与次数。ExecutionAttempt 和 ScoreAttempt 分别保留，不冒充新增 Trial。

第一版页面要求同源访问、限制请求大小并严格校验字段。数据库连接信息、模型密钥和真实服务端路径不得返回浏览器。

## 7. 工程化与交付顺序

参考 studycommit 的工程实践，保留 CodeDen 当前规范：

1. pnpm workspace 管理；前端与后端共享显式契约，禁止运行时代码反向依赖前端。
2. 一个命令启动评测平台；迁移、测试和构建另有清晰入口，不能启动时静默修改用户配置。
3. Prettier + ESLint + TypeScript；单元测试描述为中文。
4. pre-commit 格式/静态检查、密钥检查、按变更范围运行快速测试；CI 负责完整测试。
5. 数据库集成测试使用独立数据库；禁止复用 studycommit 或用户生产数据库。
6. 浏览器验收覆盖创建、进度、结果、取消、异常、移动窄屏与键盘操作。
7. 提交遵循 `type(模块): 中文描述.`；按后端、界面、工程门禁等可独立理解的目标分批提交。
8. 先开发 → review 修复 → 验证 → 按用户指示提交。当前未提交的拆包修改不能被无意混入。

### 验收清单

- [ ] 20 题 × 5 次生成恰好 100 个独立 Trial，每次重置环境和会话，无论前次结果如何都完成预定次数。
- [ ] 次数与总预算服务端校验；相同请求幂等、改变次数产生冲突，重复 Worker 回调不重复计数。
- [ ] 故障重试保留尝试与成本，不增加样本量，不通过后不能重试洗分；中断不自动重复付费。
- [ ] 通过、失败、未判定和未完成数量守恒，分母及覆盖率正确，零有效判定不产生假百分比。
- [ ] 每题显示全部试次与区间说明；同条件版本对比可用，不完整或异条件明确拒绝结论。
- [ ] 通过[重复评测专项验收](eval-repeat-experiments.md#8-验收与实施顺序)，原单次测试不替代此项。
- [ ] 页面创建 Mock 评测，后台真实执行 Agent 与 Grader，结果能查询。
- [ ] 刷新页面不重复创建、不取消后台任务。
- [ ] 多次执行及失败、取消、中断记录均可在历史查询；刷新、重新打开和服务重启后仍可找回。
- [ ] 历史支持服务端筛选和分页，详情保持原集合/配置快照；再次启动不覆盖旧记录。
- [ ] 历史查询失败不会触发评测，缺失证据和无权限不显示为成功空结果。
- [ ] 重复提交只产生一个执行任务，入队失败没有孤立记录。
- [ ] 排队及运行中取消都可操作，已有结果保留。
- [ ] 故障重启后的中断可见，不自动重新产生付费调用。
- [ ] 区分样本未通过、基础设施异常、未执行和证据不足。
- [ ] 能从失败样本定位实际提示词、模型输出与工具事件。
- [ ] Mock、估算值、缺失内容、截断内容清晰标注。
- [ ] 真实模型受服务端开关和用户付费确认双重约束。
- [ ] 样式、类型、单元、数据库集成与浏览器测试全部经过验证。

本 PRD 的交互演示独立于后端，不访问数据库、不调用模型、不上传 Trace，也不真正保存人工审核结果。演示中的“重开页面”用于说明真实产品的持久化要求；重新加载整个演示会恢复初始合成数据。
