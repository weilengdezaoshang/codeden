# 重复评测实验 · P0 需求规格

更新日期：2026-08-31。状态：待实现。本规格与 v0.9 闭环 PRD、v0.2 首版 PRD 配套，替代旧版“默认单次、重复试验延后”的要求。仅修改需求，不代表 HTML 原型、API、数据库或 Worker 已支持。

## 1. 用户能理解的完整流程

1. 准备考题：发布任务说明、初始环境和独立验收规则，先完成任务包自检。
2. 配置实验：选择评测集、可用 Agent / 模型配置、每题执行次数和预算。
3. 确认计划：例如 20 道题，每题 5 次，共 100 个试次；确认真实调用费用后启动。
4. 平台执行：每个试次准备干净环境，启动新 Agent 会话，执行任务，独立判卷，保存证据并清理。
5. 自动重复：无论前一次通过还是失败，都执行计划中其余试次，不需要用户手动重跑。
6. 汇总成绩：先看完成情况，再看每题通过几次、哪些试次失败以及资源消耗。
7. 分析并改进：用户根据失败证据修改 Agent，形成新的可识别配置版本；平台不自动修改代码。
8. 同条件再测：创建关联基线的新实验，执行相同题目及次数，比较结果；旧实验不覆盖。

这是一套仓库内不同模块协作的流程，不要求拆成多个项目。题目重复执行衡量稳定性，题目覆盖范围衡量能力范围，二者不能替代。

## 2. 对象与范围

| 对象             | 含义                            | 边界                                              |
| ---------------- | ------------------------------- | ------------------------------------------------- |
| Case             | 一道具有固定版本的题目          | 包含输入、环境与判据，不包含旧执行答案            |
| Experiment / Job | 一个被测配置的一场评测          | 首版沿用现有 job/run 身份，不另外建重复的调度实体 |
| Trial            | 一道题的一次计划内独立执行      | 由 jobId + caseId + repetitionIndex 唯一确定      |
| ExecutionAttempt | 一个 Trial 内的基础设施执行尝试 | 不是新增统计样本；保留故障与费用                  |
| ScoreAttempt     | 对同一执行产物的一次判卷调用    | 重评分不是重新执行 Agent                          |

首版一场实验只测一个配置。A/B 对比使用两个关联实验，不在一场 Job 内混入多个 Agent 版本。Agent 任务内部的修复循环、工具重试和子 Agent 都属于当前 Trial。

### 首版默认值（产品选择，不是统计充分性的承诺）

- 默认模式为“重复评测”，每题默认 5 次，可选 2–20 的整数；5 次仅为成本和操作的起点，不保证足以证明提升。
- “单次冒烟”显式设置为 1 次，仅用于验证链路，结果必须标注“不用于判断稳定性”。
- 一场实验所有题目执行相同次数，暂不支持看结果后自适应追加、提前成功停止或按题设置不同次数。
- 计划总数 N = 冻结案例数 C × 每题次数 R；服务端校验整数范围、非空集合、总试次数及预算上限，不能只依赖前端校验。
- 并发由服务端限制，不改变 R 或试次权重。执行顺序在创建时固定并记录，轮次间交错题目，避免一题独占所有执行槽位。

## 3. 创建与冻结

创建前展示 C、R、N、被测配置、每试次时间/Token/步数限制和整场预算。费用有依据时才估算，缺少定价或用量依据时显示未知；真实调用仍需明确确认，不能把估算当硬上限。

服务端在同一事务中保存实验、配置快照、全部 Trial 计划并入队。快照至少包括案例及数据集摘要、fixture/镜像摘要、Agent 代码版本、Prompt/工具/Skill/MCP 配置摘要、模型标识与参数、评分器版本、预算、次数、调度及重试策略。密钥只引用，不进入快照；不可冻结的远程模型或工具版本必须记录限制，不能承诺完全复现。

相同 requestId 与相同参数返回原实验；改变 R、预算或模型等参数后复用同一 requestId 返回冲突。排队后不得切换到最新数据集或配置。已固定版本不可用时明确失败，不偷偷替换。

## 4. 单次执行与重复调度

每个 Trial 按“准备环境 → 执行 Agent → 独立验收 → 持久化结果与产物 → 清理”执行。必须独立创建文件状态、会话、记忆及子 Agent 状态；测试记忆时从题目固定的初始记忆开始，不能继承上一试次。只允许共享不可变镜像/依赖缓存，不共享答案或可写工作目录。隐藏测试、参考解与评分器配置保持平台侧隔离；worktree 不等于进程或权限沙箱。

状态分离：Trial 的 lifecycle 为 queued / preparing / running / grading / completed / cancelled / interrupted；verdict 为 pass / fail / unknown / null。只有有效验收才能产生 pass/fail；证据不足或执行基础设施故障终结为 completed + unknown，并记录 failureStage / errorCategory。未完成执行为 null，不能提前判失败。实验 completed 表示计划全部处理结束，不表示全通过，也允许包含 unknown。

取消或整场预算耗尽后停止领取新 Trial，向正在执行的链路传递停止并清理；预算耗尽的实验状态为 failed，stopReason 为 budget_exhausted。已经判卷并提交的结果不变，未完成项单列。事先约定的单 Trial 任务预算超限，在有有效证据时可判 fail；平台整体预算耗尽不能自动判该题失败。

### 重复与故障重试

- R 是创建前计划的独立执行数量，失败不能增加、成功不能减少。
- 默认不自动重新执行已经开始调用 Agent 的 Trial。只对确认尚未调用 Agent 的可重试准备故障最多重试 1 次，使用新环境及新的 executionAttemptId，保留原故障。
- Worker 心跳丢失且无法确认外部调用是否执行时标记 interrupted，不能因重新领取就重复付费。首版不自动恢复这种不确定执行。
- 判卷传输或格式错误最多追加 1 次 ScoreAttempt，仅复用不可变执行产物，不重跑 Agent。取第一个结构有效且引用合法的判卷结果；合法 fail 不触发重评。全部无有效判卷且没有已证实必选失败时为 unknown。
- 领取使用原子租约与 fencing token；结果提交和聚合幂等，迟到 Worker 不得覆盖终态或产生第二份成绩。所有实际调用成本计入账本，包括故障尝试；缺失用量不得当 0。

## 5. 统计口径

每个题目和整场实验均保存以下计数，按 Trial 而不是 ExecutionAttempt 或 ScoreAttempt 统计：

- P：通过；F：不通过；U：已处理但未判定；M：未完成（含排队、执行中、取消和中断）。
- 恒等式：N = P + F + U + M；已处理 = P + F + U；有效判定 = P + F。
- 计划通过占比 = P / N。这个数字不是把 U/M 判为能力失败，而是表示计划内已确认通过的比例。
- 有效判定成功率 = P / (P + F)，必须同时显示有效判定覆盖率 (P + F) / N，以及 U、M；分母为 0 时显示“暂无有效判定”，不能显示 0% 或 100%。
- 运行未结束、U > 0 或 M > 0 时，明确标注“结果不完整，不用于确定性版本结论”；故障样本被排除后的成功率可能有选择偏差。

例：20 题 × 5 次 = 100 次，P=60、F=20、U=10、M=10。展示已处理 90/100、计划通过占比 60/100、有效判定成功率 60/80=75%、有效判定覆盖率 80/100，以及未判定 10、未完成 10，不能只显示“75%”。

题目汇总显示“通过 3/5 次”，逐次列出每次状态与证据。不选最好一次作为该题答案，不把多份实际回答拼成一份。完整题目按全通过、全不通过、结果波动分类；存在 U/M 的题优先标记结果不完整；R=1 只标记单次结果。全通过也只表示本次观测，不宣称长期稳定。

首版在每题有效判定成功率旁提供 95% Wilson 区间：n=P+F、p=P/n、z=1.96，中心为 (p+z²/(2n))/(1+z²/n)，半宽为 z×sqrt(p(1-p)/n+z²/(4n²))/(1+z²/n)。n=0 不计算。说明其依赖同条件独立试次假设，不消除环境相关性、选择偏差或模型漂移；R=1 不展示稳定性区间。

整体成功率只描述这个固定集合。不能把所有异质题目的 Trial 当作同分布样本套用一个 Wilson 区间，也不将整体占比外推线上质量。首版不自动提供显著性结论、pass@k 或 pass^k；未来增加时必须保留明确含义及估计方法。

总耗时区分实验墙钟时间和 Trial 累计执行时间；用量分别汇总 Agent（含子 Agent）、判卷及故障尝试。均值分母与采集覆盖率一并返回，资源缺失不能冒充节省。

## 6. 历史与同条件比较

执行历史保存 C、R、N、模式、各状态计数及冻结配置；详情按“实验 → 案例汇总 → 第几次执行 → 判据及证据”关联，所有请求校验归属。旧单次历史标记 single_smoke / R=1，不伪造重复记录，不追加到新实验的分母。

P0 提供“基于此配置创建对比实验”：复制基线的题目、次数、环境、判卷及预算快照，仅允许显式选择新的已登记被测配置，展示差异并重新确认费用。保存 baselineJobId，生成新 jobId。不能运行任意不可取得的历史 Agent；必要依赖不可用就拒绝创建。

比较前检查两个实验均为重复模式，题目及版本、环境、判卷、次数、资源/重试策略一致，且都有完整有效判定。Agent 或模型等明确声明的被测变量可以不同，其他条件不可暗中变化。条件不一致时返回具体原因，不计算“提升”结论；故障或取消的实验仍可并列查看原始数据，但标记证据不完整。

可比时展示同一道题的 P/R、整体百分点差异、资源消耗及从全通过变为非全通过的回归题。称“本次观测提高/下降”，不能自动称显著改善；不得仅因少量结果变好就自动晋级或发布。重复序号相同不代表两个版本经历同一随机过程。

只重跑失败子集、同一实验追加次数、显著性检验、自动发布门禁均延后；避免只挑失败或最好结果改变原统计总体。

## 7. API 与持久化增量

以下为待实现契约，不是现有接口支持声明：

- POST /api/jobs：在 requestId、datasetId、modelId、allowPaid 基础上增加 mode、repetitionsPerCase、agentConfigId、budgetPolicyId 和可选 baselineJobId；配置 ID 均来自服务端目录。关联基线时由服务端加载冻结快照，不信任浏览器传来的摘要。
- GET /api/catalog：返回可用配置、重复次数范围和默认值、总试次/预算限制、是否支持重复隔离执行；不支持的适配器不得伪装成可重复评测。
- GET /api/jobs 及 /:id：返回冻结计划、C/R/N、状态计数、明确分母的统计及采集覆盖率；汇总声明 statisticsVersion。
- GET /api/jobs/:id/cases：分页案例汇总；GET /api/jobs/:id/trials?caseId=...：分页独立试次，包含 repetitionIndex；原有按 trialId 的事件接口保持归属校验。
- GET /api/jobs/:id/comparison?baselineJobId=...：只读返回可比性、差异及原因，不能隐式创建或执行任务。
- Trial 唯一键为 (jobId, caseId, repetitionIndex)；执行尝试和评分尝试分别关联 Trial。新建任务应版本化契约，避免旧客户端省略次数后意外触发多倍付费；迁移前的请求保持单次语义，新版创建须显式传模式与次数。

## 8. 验收与实施顺序

| 场景                                   | 验收结果                                                    |
| -------------------------------------- | ----------------------------------------------------------- |
| 默认 20 题 × 5 次                      | 创建恰好 100 个唯一 Trial，全部有固定配置，不是失败后才补跑 |
| 非整数、0、超过 20 次、空集或超预算    | 服务端拒绝创建，无入队及付费调用                            |
| 同 requestId 重发或改变次数重发        | 前者返回同 Job，后者冲突，不生成重复 Trial                  |
| 前 4 次成功或失败                      | 第 5 次仍按计划执行，不成功早停、不失败洗分                 |
| 上次试次修改文件、记忆或子 Agent 状态  | 下次从原始快照开始，无答案泄漏                              |
| 两个 Worker 竞争、重复或迟到完成消息   | 只接受当前合法租约提交，每个 Trial 仅计一次                 |
| 准备故障后一次重试成功                 | 仍是 1 个 Trial，两个尝试均留存，故障成本不丢失             |
| Agent 已调用但 Worker 失联             | 标记中断，不自动重跑；旧 Worker 迟到提交不能覆盖            |
| 判卷格式故障后重试；判卷合法失败       | 前者不重跑 Agent，后者不以失败为由重评                      |
| P=60、F=20、U=10、M=10                 | 总数 100，已处理 90，分别返回 60/100、60/80、80/100         |
| 全部 unknown、取消或预算耗尽           | 分母 0 不产生 NaN/假 0%，未完成不被判为能力失败             |
| 题目 5/5 通过                          | Wilson 95% 区间约 56.6%–100%，不宣称真实成功率必为 100%     |
| 历史刷新、服务重启、集合更新           | R 和 Trial 证据可找回，不自动付费恢复、不覆盖快照           |
| 基线与候选同条件、条件变化或证据不完整 | 前者给出观测差异，后两者显示不可比原因，不自动晋级          |
| 旧单次历史与新重复实验                 | 旧记录仍为 1 次，不拼接数据，不称稳定性对比                 |

实施顺序：① 版本化实验/Trial/尝试契约与数据库迁移；② 隔离、调度、幂等与取消；③ 独立判卷及统计单测；④ API、历史与证据关联；⑤ 原型及页面同步、同条件对比和端到端验收。每阶段单独验收，既有单次演示测试不能替代以上测试。
